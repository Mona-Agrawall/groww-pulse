# BUILD A PRODUCTION-QUALITY FULL-STACK SMART MARKET WATCHLIST

You are acting as a **senior product designer, UX engineer, frontend engineer, backend engineer, data engineer, and creative interaction designer**.

Build the application described below **end-to-end**.

This is for the **CODE 2026 hackathon**.

The goal is NOT to create another generic stock dashboard.

The goal is to create a market intelligence experience that answers one question extremely well:

> **"What meaningfully changed since I last checked, and what deserves my attention now?"**

---

# 1. PRODUCT REQUIREMENT

The application must allow users to:

* Create and manage watchlists
* Search for stocks
* Add/remove stocks
* View current/latest market information
* View historical price information
* Return later and see what changed since their previous visit
* Understand why a particular stock deserves attention
* Persist watchlists and previous state across sessions
* Handle stale/delayed/unavailable market data
* Scale architecturally to multiple users

The application should feel like a **premium financial product**, not a CRUD application.

---

# 2. CORE PRODUCT CONCEPT

Call the intelligence layer:

# MARKET PULSE

When the user returns, the application should immediately answer:

> **What changed while you were away?**

Example:

---

### Good evening.

You were away for **7h 42m**

**3 meaningful changes**

**RELIANCE**
+3.82%
Volume 2.4× normal

**TCS**
Crossed 30-day high

**HDFCBANK**
-2.71%
Unusual volatility detected

---

The user should NOT need to inspect every stock individually.

The system should prioritize what matters.

---

# 3. IMPORTANT PRODUCT PRINCIPLE

Follow this rule everywhere:

> **Complexity should exist underneath the interface, not inside it.**

The backend can calculate dozens of metrics.

The user should see:

> "RELIANCE deserves attention because it moved 3.8% with unusually high volume."

Not:

> RSI 71 / MACD 0.43 / ATR 52 / Bollinger 2.1 / etc.

The product should feel intelligent without claiming to predict the market.

# 9. GEMINI AI

Use the **Gemini API** for natural-language explanations.

Do NOT use Gemini to calculate financial facts.

The deterministic backend calculates:

```text
price change
volume anomaly
volatility change
breakout
recent high/low
relative performance
attention score
```

Then Gemini receives verified facts.

Example input:

```json
{
  "symbol": "RELIANCE",
  "priceChange": 3.82,
  "volumeMultiple": 2.4,
  "crossed30DayHigh": true,
  "timeSinceLastSeen": "7h 42m"
}
```

Gemini generates a concise explanation:

> "RELIANCE deserves attention because it gained 3.8% while trading at roughly 2.4× its normal volume and crossed its recent high."

Never allow the AI to invent:

* prices
* percentages
* events
* news
* financial claims

The AI is an **explanation layer**, not the source of truth.

**Attention Score ≠ prediction score.**

> "This changed enough that you should probably look at it."
